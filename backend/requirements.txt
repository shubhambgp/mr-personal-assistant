# --- retrieval (RAG) ---
# Qdrant is the ONLY store for the document corpus: vectors, text and metadata.
# Postgres is deliberately not involved — a second store would mean dual-write
# and orphaned vectors on delete.
#
# No server and no Docker required in dev or CI: qdrant-client runs the real
# engine in-process (path= for on-disk, :memory: for tests), and QDRANT_URL
# points at a real server in production. Same API for all three.
#
# NOT fastembed: its BM25 model is purely lexical, yet the package pulls 66 MB
# of onnxruntime that the model never uses. Qdrant's Modifier.IDF computes IDF
# server-side, so app/services/vectors.py sends term frequencies from a small
# tokeniser used identically at ingest and query time.
qdrant-client==1.19.0

# --- agenda (Gmail + Google Calendar) ---
# Promoted from the dev block below: httpx is now a RUNTIME dependency, because
# the Google integration is plain REST over httpx and NOT google-api-python-client
# or google-auth-oauthlib.
#
# What those would have added: google-api-python-client is discovery-document
# driven and pulls httplib2 + uritemplate + protobuf; google-auth-oauthlib pulls
# requests-oauthlib -> oauthlib -> requests. Five transitive packages and a second
# HTTP stack alongside the one FastAPI already uses, both sync-first, so every
# call would need a to_thread.
#
# What we actually need is three form-encoded POSTs to oauth2.googleapis.com
# (exchange, refresh, revoke) and GETs against two documented REST endpoints.
# CLAUDE.md §6: do not add a dependency to work around something the standard
# library does. RFC 2822 construction is email.message.EmailMessage; base64url is
# base64.urlsafe_b64encode; the id_token needs no signature verification because
# we never read it — userinfo is called with the access token over TLS instead.
#
# httpx also buys the test story: httpx.MockTransport is how every Google call is
# exercised in the no-network `pytest tests` job. A discovery-based client would
# have needed a live discovery fetch or a much larger fake.
httpx==0.28.1

# Google refresh tokens are encrypted at rest with AES-256-GCM. This is the one
# place §6 does not apply: hmac and hashlib authenticate, they do not encrypt, and
# there is no AEAD in the standard library.
#
# Considered and rejected: pgcrypto's pgp_sym_encrypt, because the key would
# travel inside SQL text and therefore into pg_stat_activity and any statement
# log; and storing nothing at all (access-token-only, re-consent hourly), which is
# genuinely more secure and makes "what needs my attention this morning"
# impossible. Fernet was rejected in favour of raw AESGCM: Fernet is CBC+HMAC
# with a timestamp we do not want, AESGCM is one primitive and a dozen lines.
# Apache-2.0 / BSD dual-licensed, maintained by PyCA.
cryptography==50.0.0
